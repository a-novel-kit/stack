# Upgrading to v1.43.0

The `a-novel` CLI settles on one exit code for a usage error and one `--format` flag for machine
output, rejects a flag value it does not know instead of falling back silently, and lets the daemon
resolve target shorthands.

## Do I need to act?

**Only if** a script of yours reads one of these. Typing commands by hand works as before, except
that a mistyped value now fails instead of being ignored.

| You depend on                                                                                   | Change it to                                    |
| ----------------------------------------------------------------------------------------------- | ----------------------------------------------- |
| `run ps --json`                                                                                 | `run ps --format=json`                          |
| `run watch --json=false`                                                                        | `run watch --format=text`                       |
| exit status 1 after a usage error (wrong argument count, unknown subcommand, bad argument)      | exit status 2                                   |
| `core sync -j 0` running every repository at once                                               | `core sync -j <n>` with a positive count        |
| `--type` tolerating spaces or capitals (`-t 'go, pnpm'`, `-t Go`)                               | lowercase words, comma-separated: `-t go,pnpm`  |
| a shorthand such as `service-json-keys/rest` landing in the stack `$A_NOVEL_STACKS` names first | the daemon's default stack, or `--stack <name>` |
| `core restart` succeeding while the shutdown leaves targets running                             | a non-zero exit; stop them, or retry            |

`--json` keeps working on `run ps` and `run watch` for now, with a deprecation notice on stderr.

Pull the stack and rebuild the CLI to pick up the release:

```bash
git -C ~/git-projects/a-novel pull --ff-only
a-novel install
```

## Exit codes

| Status | Meaning                                                                                       |
| ------ | --------------------------------------------------------------------------------------------- |
| 0      | Success                                                                                       |
| 1      | The command failed                                                                            |
| 2      | Usage error: an unknown command or flag, a flag value outside its set, a wrong argument count |
| 130    | Interrupted                                                                                   |

`secrets exec`, `run exec` and `--sandbox` exit with their child's status; a child the interrupt
ends exits 130. Before this release, a wrong argument count and an unknown subcommand exited 1, as
v1.35.0 published, and so did the argument checks of `core bot-comment`, `secrets set`,
`secrets exec`, `core stacks new` and `core stacks prune`. A script telling a usage error apart from
a failure now tests for 2:

```bash
a-novel run start "$TARGET"
case $? in
  0) ;;
  2) echo "usage error" ;;
  *) echo "the command failed" ;;
esac
```

## Machine output

Every command with a machine form takes `--format`:

| Command     | Values                    | Default |
| ----------- | ------------------------- | ------- |
| `run ps`    | `text`, `json`            | `text`  |
| `run watch` | `json`, `text`            | `json`  |
| `run env`   | `shell`, `json`, `dotenv` | `shell` |

```bash
# before
a-novel run ps --service="$SERVICE" --json
# after
a-novel run ps --service="$SERVICE" --format=json
```

## Flag values are checked

`--mode`, `--one-shots`, `--format`, `--stream`, `--kind` and `--type` accept only their listed
values, and shell completion offers them. A typo such as `run start --mode=contaner` used to start
the target in go-exec mode; it now exits 2 and names the accepted values. `--type=go,bogus` fails
the same way instead of dropping `bogus`, and `--type` no longer trims or lowercases its words.

`--jobs` must be a positive number in `test`, `build` and `core sync` alike. Leave it out to keep
each command's default.

## Target shorthands resolve in the daemon

A shorthand, `<service>/<target>` or `<service>/infra/<name>`, resolves against the daemon's
default stack, the one every other request already uses, instead of the first entry of the
`$A_NOVEL_STACKS` your shell holds. Both agree unless the shell's variable changed after the
daemon started; `core stacks list` reports that case. Pass `--stack <name>` or the full
`<stack>/<service>/<target>` to pick another stack.

## Stopping the daemon fails the same way everywhere

`core kill --force`, `core restart`, `core prepare-reinstall` and `install` share one stop. A
shutdown that leaves targets running fails each of them and names the targets, and `install` now
stops on a daemon that does not answer or exits too slowly, where it used to warn and continue.

## The `run ui` dashboard

The dashboard draws in the colors of `test`, `build` and `core sync`, and adapts to light
terminals. Nothing to change.
