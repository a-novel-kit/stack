# Upgrading to v1.35.0

The `a-novel` CLI fails on an unknown subcommand under any command group, as it already did at the
root.

## Do I need to act?

**Only if** a script calls a subcommand that the CLI does not have. Such a call printed the help of
its group and exited 0, so the script kept running on the wrong output. The call now fails with
`unknown command` and exits 1. The likeliest calls are `run stacks` and `run service status`, which
v1.34.1 removed. Replace them as the [v1.34.1 guide](./v1.34.1.md) shows.

## Check a call

```bash
a-novel run stacks; echo "exit $?"
# Error: unknown command "stacks" for "a-novel run"
# exit 1
```

A typo gets a suggestion, as at the root: `a-novel core stakcs` answers `Did you mean this? stacks`.

## What still prints help

- `a-novel <group>` with no argument, `a-novel <group> --help` and `a-novel help <group>` print the
  group's help and exit 0.
- `a-novel completion` keeps cobra's behavior: an unknown shell prints its help and exits 0.
