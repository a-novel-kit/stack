# Upgrading to v1.42.0

The `a-novel` CLI drops `repo create` and `repo update`. a-novel/infra's GitHub root now manages the
config of every repository in both organizations.

## Do I need to act?

**Only if** you ran `a-novel repo create` or `a-novel repo update`, by hand or in a script. Both now
fail with `unknown command "repo" for "a-novel"` and exit 1. Every other command works as before.

Pull the stack and rebuild the CLI to pick up the release:

```bash
git -C ~/git-projects/a-novel pull --ff-only
a-novel install
```

## Change repository config in a-novel/infra

Settings, team access, labels, rulesets, environments, scoped secret access and the governance keys
live in the GitHub root, `environments/production/github`. Change them in a pull request there, and
its merge applies them. Required checks, environments and secret access follow each repository's
workflows on its default branch. Within 10 minutes of a merge that changes them, the root's sweep
applies the new set, so nothing needs running:

```bash
# before, after a main.yaml change
a-novel repo update --all
# after: nothing
```

A governance key rotates in Secret Manager instead of Bitwarden, as infra's
[Governance secrets](https://github.com/a-novel/infra/blob/master/docs/runbooks/secrets.md#governance-secrets)
runbook describes.

## Create a repository in a-novel/infra

A repository is an entry under `repositories` in the root's `terraform.tfvars`. Its class sets its
settings, and a service or a platform starts from its template repository:

```hcl
"a-novel/service-example" = {
  class       = "service"
  description = "Says what the service does, in one sentence."
  topics      = ["agora-storyverse", "go", "golang", "microservice"]
}
```

[Create a repository](https://a-novel-kit.github.io/stack/sysadmins/create-repository) walks through
the steps that follow, from the release App to the Discord role.

## Delete the Bitwarden token

The CLI no longer reads Bitwarden. A core member deletes the token stored for `repo update`:

```bash
a-novel secrets rm BWS_ACCESS_TOKEN
```

## Notes

Each repository now owns its governance workflows and `CODEOWNERS`. A copy may still open with a
"Managed by `a-novel repo update`" banner: delete it the next time you edit that file.
